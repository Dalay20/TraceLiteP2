PROYECTO PARCIAL TRACELITE

Avance parcial
Primera versión funcional de un sistema ligero de trazabilidad en C
Descripción
Se requiere desarrollar la primera versión de TraceLite, una solución de trazabilidad distribuida para
GNU/Linux inspirada en OpenTelemetry y Grafana Tempo. En esta etapa se implementará la generación de
trazas entre procesos, su transmisión a un recolector y una visualización básica en terminal. No se utilizarán los
SDK oficiales de estas plataformas.
Objetivo del avance
Demostrar que una solicitud puede recorrer al menos dos servicios o procesos, generar spans relacionados
mediante un mismo Trace ID y transmitirlos correctamente a un proceso recolector empleando mecanismos de
Sistemas Operativos.
Requerimientos mínimos
1. Arquitectura de procesos
Definir un proceso principal y al menos dos servicios o procesos hijos para atender solicitudes. Crear procesos
mediante fork() y utilizar la función exec() para iniciar al menos uno de los componentes. Documentar las
responsabilidades y relaciones entre procesos.
2. Instrumentación de operaciones (spans)
Registrar para cada operación: Trace ID, Span ID, Parent Span ID (vacío para el span raíz), nombre del servicio,
operación, inicio, fin, duración en milisegundos y estado (éxito/error). Los spans de una solicitud deberán
compartir el mismo Trace ID y reflejar correctamente la relación padre-hijo.
3. Propagación de contexto
Transmitir el Trace ID y el identificador del span padre cuando una solicitud pase del Servicio A al Servicio B.
Cada servicio generará su propio Span ID sin perder la correlación con la solicitud original.
4. Comunicación y recolección
Implementar un proceso Collector Lite que reciba los spans de los servicios mediante pipes, memoria
compartida o sockets locales. Se deberá justificar el mecanismo elegido y describir el formato de los mensajes
enviados.
5. Visualización inicial en terminal
Mostrar los spans recibidos agrupados por Trace ID, con servicio, estado, duración y relación padre-hijo. En esta
etapa bastará una salida textual funcional; no se exige todavía un dashboard de actualización periódica.
6. Prueba básica de funcionamiento
Generar como mínimo tres solicitudes completas y demostrar al menos un escenario con incremento aleatorio
del tiempo de respuesta o un error. La anomalía deberá quedar registrada en los datos del span
correspondiente.

Condiciones técnicas
• Implementación principal en lenguaje C sobre GNU/Linux; compilación mediante Makefile.
• El mecanismo de comunicación deberá ser funcional entre procesos independientes; no basta con imprimir
trazas ficticias.
• Utilizar tiempos reales medidos en ejecución. Para calcular duraciones se recomienda
clock_gettime(CLOCK_MONOTONIC).
• No se permite delegar las funciones principales a OpenTelemetry SDK, Grafana Tempo u otra plataforma de
trazabilidad.
Entregables del avance parcial
• Informe de avance: descripción, diagrama de arquitectura de software, modelo de procesos, mecanismo IPC,
formato de span y capturas de las pruebas.
• Código fuente en C, Makefile y archivo README con instrucciones para compilar y ejecutar.
• Video breve con explicación de la arquitectura y demostración de al menos tres trazas correlacionadas.
• Checklist indicando las funcionalidades implementadas y aquellas pendientes para la entrega final.
Checklist de verificación
☐ Se crean al menos dos servicios/procesos y se utiliza fork() y exec().
☐ Los spans contienen los identificadores, tiempos y estados solicitados.
☐ El contexto de trazabilidad se propaga correctamente entre servicios.
☐ Los spans llegan al recolector mediante un mecanismo IPC.
☐ Se muestran trazas completas y una prueba de anomalía en terminal.
☐ Se entregan informe, código, Makefile, README y video.
